Ты — senior fullstack разработчик. Сгенерируй полностью рабочий проект “Bond Tracker” для локального использования.

СТЕК (ОБЯЗАТЕЛЬНО)
- Frontend: React + Vite + TypeScript
- Styling: styled-components (обязательно, но можно добавлять другие UI библиотеки)
- Requests: axios (обязательно)
- Routing: react-router (если нужен)
- Backend: NestJS + TypeScript (обязательно)
- Storage: один JSON-файл на диске (обязательно)

ЦЕЛЬ
Приложение для учета облигаций:
- какие облигации куплены, когда, по какой цене, количество
- общая сумма вложенных денег
- даты купонных выплат, даты погашения
- общий доход (ожидаемый и фактический, если отмечать “получено”)
- удобно добавлять/редактировать/удалять данные
- опционально графики (например вложения по времени, выплаты по месяцам)

КЛЮЧЕВОЕ ТРЕБОВАНИЕ ПО ДАННЫМ
Данные должны:
1) читаться из JSON-файла при запуске
2) после любых изменений (CRUD) сохраняться обратно в этот JSON-файл
Сохранение должно быть безопасным (атомарная запись: temp file + rename), с простой валидацией.

АРХИТЕКТУРА РЕПОЗИТОРИЯ
Сделай репозиторий с двумя папками:
- /server — NestJS
- /client — Vite React
Добавь корневой package.json со скриптами:
- dev: одновременно запускает server и client
- dev:server, dev:client
- build: сборка client
- start: запуск production (опционально)
Используй concurrently (или аналог) для параллельного запуска.

BACKEND (NestJS)
Сделай модуль DataModule (или BondsModule) который:
- читает/пишет data.json из папки server (например: server/data/data.json)
- эндпоинты (REST):
  - GET  /api/data                 -> вернуть весь JSON
  - PUT  /api/data                 -> перезаписать весь JSON (с валидацией)
  - (желательно) CRUD-эндпоинты:
    - GET  /api/bonds
    - POST /api/bonds
    - PATCH/PUT /api/bonds/:id
    - DELETE /api/bonds/:id
    - GET  /api/purchases
    - POST /api/purchases
    - PATCH/PUT /api/purchases/:id
    - DELETE /api/purchases/:id
    - GET/POST/PATCH/DELETE для payments (если решишь хранить фактические выплаты)
Но если CRUD слишком долго — делай PUT /api/data как основной, а на фронте управляй структурой. Однако предпочтительнее CRUD.

- Валидация DTO: class-validator + class-transformer
- CORS: включить для dev
- Конфиг: порт 3001
- Отдача статики: в production server может отдавать собранный client (опционально)

РАСЧЕТЫ
Сделай практичные расчеты:
- invested = Σ(quantity * pricePerBond + commission)
- couponPerPeriod = faceValue * couponRateAnnual / couponFrequencyPerYear
- expectedIncome можно считать по расписанию (если есть schedule) или приблизительно:
  - на год: quantity * faceValue * couponRateAnnual
  - до maturity: по количеству периодов до maturityDate
Если трудно корректно строить расписание по датам — сделай ручной ввод payments, а expectedIncome считай как сумму payments where type=coupon.

ДЕНЕЖНЫЕ РАСЧЕТЫ
Избегай ошибок float:
- храни деньги в “копейках/центах” (integer) или сделай helper для округления и нормализации.
Если используешь number — везде округляй до 2 знаков и будь последователен.

ДОП. ТРЕБОВАНИЕ: РУЧНЫЕ ВЫПЛАТЫ (ОБЯЗАТЕЛЬНО)
При добавлении/редактировании облигации пользователь должен иметь возможность вручную указать список выплат:
- date (ISO строка YYYY-MM-DD)
- amount (сумма выплаты)
- type: "coupon" | "redemption" (купон или погашение)
- received: boolean (по умолчанию false)
- note (опционально)

Эти выплаты хранятся в JSON и редактируются из UI:
Вариант А (предпочтительно): выплаты вложены в облигацию:
bond.payments: Payment[]
Вариант Б: отдельный массив payments с bondId — но CRUD и UI должны позволять добавлять выплаты прямо из формы облигации.

UI ДЛЯ ВЫПЛАТ
- В форме облигации сделай секцию “Выплаты”:
  - таблица строк (date, amount, type, received)
  - кнопки Add / Remove
  - валидация: date обязателен, amount > 0
  - сортировка по дате
- В деталях облигации — список выплат + переключатель received.

РАСЧЕТЫ С УЧЁТОМ РУЧНЫХ ВЫПЛАТ
- expectedIncome = сумма всех bond.payments.amount где received=false (или всех coupon, если хочешь отдельно)
- receivedIncome = сумма всех payments.amount где received=true
- ближайшие выплаты на дашборде — из всех payments по всем облигациям (date >= today), сортировка, top 5

BACKEND
- DTO/валидация для массива payments в BondDto
- при сохранении облигации/выплат — запись в JSON атомарно
